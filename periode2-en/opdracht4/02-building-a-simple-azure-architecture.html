Building a Simple Azure Architecture

Time to build. This page walks you through deploying a basic static website or web app on Azure from nothing to a live URL. Follow the steps in order, and take a screenshot after every step — you will need them for your logbook.

Two simple routes

There are two beginner-friendly ways to host a small site on Azure. Pick the one that matches your proposal:

RouteBest for
Azure Storage static website hostingPlain HTML/CSS/JavaScript — no server-side code. Cheapest and simplest option.
Azure App Service (Free F1 tier)A web app that needs a bit more than static files, or that you want to manage as a "real" web app resource.

Steps

  1. Sign up for an Azure account. Use the Azure free account (azure.microsoft.com/free) if you don't have access yet, or use the student/school-provided credits or sandbox environment your teacher points you to. Either way, make sure you know which subscription you are working in before you create anything.
  2. Create a Resource Group. In the Azure portal, search for "Resource groups" and create a new one (for example rg-prototype-yourname). A resource group keeps everything you build for this assignment together, so you can find it, manage it and clean it up as one unit.
  3. Create your resource.
    • For a static website: create a Storage account (Standard performance, locally-redundant storage is fine), then open Static website under Data management and enable it. Note the primary endpoint URL Azure gives you.
    • For a web app: create an App Service, choose the Free F1 pricing tier, and pick a runtime that matches your code (for example Node.js or a static HTML runtime).
  4. Upload or deploy your content. For static website hosting, upload your index.html (and any CSS/JS/images) into the $web container using the Azure Portal, Azure Storage Explorer, or the Azure CLI. For App Service, deploy your files using the Deployment Center (for example connecting a GitHub repository), FTP, or the CLI.
  5. Test the live URL. Open the endpoint URL Azure gave you in a browser. Check that your pages load, links work, and nothing is broken. Test on your phone too, if your design is meant to be responsive.
  6. Take screenshots for your logbook. Capture the resource group, the resource configuration screen, and the live site in the browser with its URL visible. These screenshots are your evidence that you actually built and deployed something — not just planned it.
💡 Use the free tier responsibly
Free-tier and student-credit resources come with limits (storage size, bandwidth, compute hours). For a small prototype like this you won't come close to those limits — but get into the habit of checking a service's pricing tier before you create it, and delete resources you are no longer using. This is exactly the kind of cost-awareness the AZ-900 exam expects you to understand.
⚠️ Document your security settings
Before you move on, note down the security choices Azure already made for you and any you made yourself — you will need them for the documentation page. At minimum, check: is HTTPS enforced (Azure Storage and App Service both enable this by default), and have you made sure your storage account access keys or connection strings are not shared publicly (never paste them into a public GitHub repo or hand them in as part of your homework)?
