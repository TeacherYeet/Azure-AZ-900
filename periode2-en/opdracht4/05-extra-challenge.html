Extra Challenge: Level Up Your Prototype

This page is not required and does not count towards your exam portfolio. Try it if your basic prototype is already working and you want to push it further, or simply want to explore what else Azure can do.

★ Bonus assignment
Pick one (or more) of the stretch goals below and add it to your working prototype. Document what you added the same way you documented the rest — a short description is enough.

Stretch goals

  1. Add a custom domain and Azure CDN. Instead of the default *.z13.web.core.windows.net style URL, point a custom domain at your static website, and put Azure CDN (or Azure Front Door) in front of it to cache your content closer to visitors and add HTTPS on your own domain name.
  2. Connect a simple database to make your site dynamic. Add Azure Table Storage or the Cosmos DB free tier and use it to store something simple — a guestbook, a visitor counter, a list of items — that your page reads or writes to. This turns a static site into a small dynamic application.
  3. Set up basic CI/CD. If you used (or switch to) Azure Static Web Apps, it comes with a genuinely simple built-in GitHub Actions workflow: connect your GitHub repository once, and every push to your main branch automatically rebuilds and redeploys your site — no manual upload needed. This is a small taste of how real-world teams ship code continuously.
💡 Why this is worth doing
Employers value people who look beyond the minimum requirement. Even a small extra feature — a custom domain, a bit of dynamic data, or an automated deployment — shows you understand how these Azure services fit together, and gives you something concrete to talk about in a job interview.
