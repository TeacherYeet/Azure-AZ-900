Review: Azure Architecture and Services

A compact reference covering Azure's physical/management structure and its core service categories: compute, networking, storage, and identity & security. This maps to Microsoft's "Describe Azure architecture and services" exam domain.

Physical and logical structure

ConceptWhat it is
RegionA set of datacenters in close proximity, deployed within a defined latency perimeter. Azure has 60+ regions worldwide.
Availability zoneA physically separate datacenter within a region, with independent power, cooling, and networking. Using multiple zones protects against datacenter-level failure.
Region pairEach region is paired with another region at least 300 miles away. Some services replicate automatically to the pair; updates roll out sequentially across pairs to reduce downtime.
Resource groupA container that groups related resources sharing the same lifecycle. Every resource belongs to exactly one resource group.
SubscriptionA billing boundary and an access-control boundary — it groups resource groups and controls who can provision what.
Management groupA container above subscriptions, used to apply governance conditions across multiple subscriptions at once. Up to six levels deep.

Hierarchy, top to bottom: management groups → subscriptions → resource groups → resources.

Compute options

ServiceBest for
Virtual Machines (VMs)IaaS. Full control over the OS. Good for lift-and-shift and dev/test.
VM scale setsAutomatically scale a group of load-balanced, identical VMs out (add) or in (remove) based on demand.
Azure App ServicePaaS for hosting web apps and APIs (.NET, Node.js, Java, Python, PHP) without managing servers.
Containers (Container Instances / AKS)Lightweight, no OS to manage. Azure Container Instances runs single containers; Azure Kubernetes Service (AKS) orchestrates containers at scale.
Azure FunctionsServerless, event-driven code — you focus purely on your logic, not infrastructure. Pay only when the function runs.
Azure Virtual DesktopA full desktop virtualization experience delivered from the cloud, with true multi-session support.

Networking

  • Virtual Network (VNet) — lets Azure resources communicate with each other, the internet, and on-premises networks.
  • Load balancing — distributes traffic across multiple instances (e.g. a VM scale set) to keep applications available and responsive.
  • VPN Gateway — sends encrypted traffic between an Azure VNet and an on-premises location over the public internet.
  • ExpressRoute — extends an on-premises network into Azure over a private connection (not over the public internet), via a connectivity provider.
  • Azure DNS — hosts DNS domains and provides name resolution using Microsoft's global network of name servers.
💡 Exam tip
VPN Gateway uses the public internet (encrypted); ExpressRoute uses a private, dedicated connection. ExpressRoute is generally faster and more reliable, but also more expensive to set up.

Storage

Every storage account needs a globally unique name. Key storage services:

  • Blob storage — massive amounts of unstructured data (text, binary, images, video).
  • Disk storage — disks used by virtual machines.
  • Azure Files — highly available network file shares accessed via the SMB protocol.

Access tiers (for blob data, switchable at any time):

TierUse case
HotData accessed frequently.
CoolData accessed infrequently, stored for at least 30 days.
ArchiveData rarely accessed, stored for at least 180 days, higher retrieval latency.

Redundancy options (higher durability = more copies, in more places):

OptionHow data is replicated
LRS (Locally redundant storage)Three copies within a single datacenter in the primary region.
ZRS (Zone-redundant storage)Copies spread across three availability zones in the primary region.
GRS (Geo-redundant storage)LRS in the primary region, plus asynchronous replication to a secondary region.
GZRS (Geo-zone-redundant storage)ZRS in the primary region, plus replication to a secondary region — the highest durability.

Identity, access, and security

  • Microsoft Entra ID (formerly Azure Active Directory) — Azure's cloud-based identity and access management service: authentication, single sign-on (SSO), and device/application management.
  • Multi-factor authentication (MFA) — requires two or more of: something you know (password), something you possess (a phone/token), something you are (biometrics).
  • Azure RBAC (Role-Based Access Control) — fine-grained access management: grant users only the access they need, scoped to a management group, subscription, resource group, or resource.
  • Zero Trust — a security model built on "never trust, always verify": explicitly verify every request, use least-privilege access, and assume breach.
  • Defense in depth — a layered security approach (physical, identity, perimeter, network, compute, application, data) so a breach of one layer doesn't compromise the rest.
  • Microsoft Defender for Cloud — a monitoring service providing threat protection, security recommendations, and a secure score across Azure and on-premises resources.
