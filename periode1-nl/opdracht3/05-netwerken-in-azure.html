Netwerken in Azure

Resources in de cloud moeten met elkaar, met het internet en soms met jouw eigen bedrijfsnetwerk kunnen praten. Deze les geeft je op AZ-900-niveau de belangrijkste netwerkbegrippen in Azure — zonder de diepe netwerktheorie.

Azure Virtual Network (VNet)

Een Azure Virtual Network (VNet) is het fundament van netwerken in Azure. Het stelt Azure-resources in staat om veilig te communiceren:

  • met elkaar,
  • met het internet, en
  • met on-premises netwerken (het netwerk van je eigen organisatie).

Je kunt een VNet opdelen in kleinere stukken, subnets genoemd, om resources logisch te groeperen en verkeer te beheren. Ook kun je twee VNets aan elkaar koppelen via peering, zodat resources in beide netwerken met elkaar kunnen communiceren alsof ze in hetzelfde netwerk zitten.

Om te bepalen welk verkeer een resource wél of niet mag ontvangen, gebruik je network security groups — daarmee open je bijvoorbeeld specifiek poort 80 voor HTTP-verkeer naar een virtuele machine.

💡 Publieke versus private endpoints
Een resource kan bereikbaar zijn via een public endpoint (een publiek adres, toegankelijk via internet) of via een private endpoint (alleen bereikbaar binnen je eigen virtual network). Voor gevoelige resources is een private endpoint veiliger, omdat het verkeer nooit het openbare internet op hoeft.

Hybride verbindingen: VPN Gateway en ExpressRoute

Veel organisaties willen hun eigen (on-premises) netwerk verbinden met Azure. Daarvoor zijn twee opties:

DienstHoe het werkt
VPN Gateway Verstuurt versleuteld verkeer tussen een Azure virtual network en een on-premises locatie, over het publieke internet.
Azure ExpressRoute Breidt je on-premises netwerk uit naar Azure via een privéverbinding, aangeboden door een connectivity provider — dus niet over het openbare internet.

Kort gezegd: een VPN Gateway is de goedkopere, versleutelde route over het gewone internet; ExpressRoute is een privé, doorgaans stabielere en snellere verbinding buiten het publieke internet om.

Load balancing

Wanneer je meerdere instanties van een applicatie draait (bijvoorbeeld meerdere VM's in een scale set), zorgt load balancing ervoor dat inkomend verkeer evenwichtig over die instanties wordt verdeeld. Dit voorkomt dat één instantie overbelast raakt terwijl andere nauwelijks gebruikt worden, en verhoogt zo de betrouwbaarheid en prestaties van je applicatie.

Azure DNS

Azure DNS is de dienst waarmee domeinnamen worden vertaald naar IP-adressen, zodat resources vindbaar zijn op naam in plaats van op adres. Kenmerken:

  • Betrouwbaarheid en snelheid dankzij een wereldwijd netwerk van DNS-naamservers (met Anycast-netwerktechnologie).
  • Beveiliging via Azure Resource Manager, met role-based access control, monitoring en logging.
  • Eén DNS-dienst om zowel je Azure- als externe resources te beheren.
  • Ondersteuning voor volledig aangepaste, private domeinnamen binnen je eigen virtual networks.
  • Alias records die rechtstreeks naar een Azure-resource kunnen verwijzen (handig als het IP-adres van die resource verandert).
